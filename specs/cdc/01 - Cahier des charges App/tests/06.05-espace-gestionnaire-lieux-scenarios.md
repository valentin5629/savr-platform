**Décisions Val 2026-06-07 (6 floues tranchées, propagées §06.05 + §09)** :
- **F1** : toggle « email à chaque nouvelle collecte programmée sur un de mes lieux » **supprimé V1** (aucun template ne l'implémentait — pattern sobriété 2026-05-30). Réintroduction V1.1 avec template dédié si demande terrain.
- **F2** : **statut consolidé événement** défini — `Annulé` = toutes collectes `annulee` ; `Terminé` = toutes collectes terminales (`realisee`/`cloturee`/`realisee_sans_collecte`/`annulee`) dont ≥ 1 `realisee`, `cloturee` ou `realisee_sans_collecte` *(une collecte AG sans excédent compte réalisée, décision Val 2026-10-18)* ; `En cours` = sinon (≥ 1 collecte non terminale). **Mapping affichage statut collecte côté client : supersédé le 2026-06-30 (divergence UX-STATUTS)** — désormais `brouillon`/`programmee` → « Créée », `validee` → « Validée », `en_cours`/`realisee` → « En cours », `realisee_sans_collecte` → « Sans excédents » (puis « Réalisée » depuis le 2026-10-09, décision Val), `cloturee` → « Réalisée », `annulee`/`annulation_demandee` → « Annulée », `rejetee_par_prestataire` → « Créée » (masqué). Source canonique : §06.04. L'ancien mapping (`programmee`/`validee` → « Programmée », `realisee`/`cloturee` → « Réalisée ») ne s'applique plus. *(Le statut consolidé événement ci-dessus reste inchangé.)*
- **F3** : **brouillons tiers exclus** de la visibilité gestionnaire — prédicat SELECT `evenements` : `(organisation_id = self OR (date_evenement IS NOT NULL AND au moins une collecte hors brouillon))` — garde sur le statut depuis le 2026-10-24 (un brouillon a une date, celle de ses collectes).
- **F4** : UPDATE `evenements` gestionnaire **gaté par `f_collecte_editable(evenements.id)`** (aligné workflow traiteur).
- **F5 BLOQUANT** : matrice `users` §09 — gestionnaire_lieux aligné traiteur_manager : INSERT + UPDATE `organisation_id = self` (invitation + désactivation). Garde UI : pas d'auto-désactivation.
- **F6 BLOQUANT** : matrice `factures` §09 — gestionnaire_lieux SELECT `organisation_id = self` (ses propres factures uniquement ; factures des traiteurs toujours invisibles). Miroir `shared.fichiers` (scope strict = RLS table factures). pgTAP `fichiers_facture_gestionnaire_denied` scindé en 2.
